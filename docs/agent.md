# Агент на серверах: docker, systemd и сервера без агента

*English summary: srvmon-agent runs either as two containers (`docker` mode) or, on hosts where docker is unwelcome such as Proxmox VE, as a sandboxed systemd service (`systemd` mode). The add wizard picks the mode (`auto` = docker if the server has it, systemd on a Proxmox VE node without docker). To add an agent to a server that has none, open its passport, row "agent token" → "token for a manual install", and run the shown command as root (`curl -fsSL https://<panel>/agent/install.sh | sudo SRVMON_TOKEN=<token> sh`) — for example in the panel's own terminal. The panel stores tokens only as hashes, so an existing token cannot be shown; issue a new one instead, the old one is revoked once an agent pushes with the new token. Servers without any agent are marked "ssh only".*

## Два режима агента

| | docker | systemd |
| --- | --- | --- |
| Где подходит | обычные сервера, где уже есть docker или его можно поставить | гипервизоры (Proxmox VE) и хосты, где docker ставить нельзя или не хочется |
| Что запускается | контейнеры `srvmon-agent` и `srvmon-dockerproxy` | сервис `srvmon-agent.service`, бинарь `/usr/local/lib/srvmon-agent/srvmon-agent` |
| Контейнеры в панели | да | нет, раздел docker пуст, и это нормально |
| Логи в панели | `/var/log/syslog` + логи контейнеров | `/var/log/syslog`, а если его нет (Proxmox VE 8), то journald |
| Логи самого агента | `docker logs srvmon-agent` | `journalctl -u srvmon-agent` |
| S.M.A.R.T. | включается кнопкой на экране сервера | так же |
| Обновление | панель сама, по SSH | панель сама, по SSH, без sudo |

На ноде Proxmox docker лучше не ставить: он переписывает правила iptables/nftables и живёт в cgroup рядом с KVM и ZFS. А агент внутри LXC-контейнера видит только этот контейнер, а не ноду. Поэтому для гипервизора есть режим systemd.

Режим агента видно в паспорте сервера, в строке «агент», рядом с версией: `· docker` или `· systemd`.

## Новый сервер: мастер добавления

В мастере (`+ сервер`), на шаге «ключ и агент», отметьте «установить srvmon-agent» и выберите режим:

- **auto** (по умолчанию). Если docker на сервере есть, ставится docker-агент. Если это нода Proxmox VE без docker, ставится systemd-сервис, docker не устанавливается. В остальных случаях docker будет установлен, как раньше.
- **docker** или **systemd** задают режим явно.

Панель сама скопирует бинарь агента со своего образа по SSH. Серверу не нужен доступ к GitHub или реестру образов.

Повторный запуск мастера с другим режимом заменяет агента: systemd-сервис убирает контейнеры агента, которые ставила панель, и наоборот.

## Сервер уже добавлен, но агента нет

Такой сервер помечен **◇ только ssh** (а не offline) и не учитывается в счётчике «up» на обзоре. Терминал и AI-агент с ним работают, но метрик, дисков и алертов нет.

Чтобы поставить агента:

1. Откройте сервер → паспорт → строка **«токен агента»** → **«токен для ручной установки»**. Панель покажет токен и готовые команды. Токен показывается один раз.
2. Скопируйте первую команду (systemd-сервис, без docker) и выполните её на сервере от root. Удобнее всего прямо в терминале панели (`>_ терминал`): там вы заходите под пользователем `srvmon`, поэтому добавьте `sudo`:

   ```bash
   curl -fsSL https://<панель>/agent/install.sh | sudo SRVMON_TOKEN=a_... sh
   ```

   Под root (например, на свежем Proxmox без sudo) команда та же, но без `sudo`.
3. Через полминуты статус сменится на **● online**, а в паспорте появится `· systemd`.

То же можно поручить AI-агенту: «выполни на <сервер>: <команда>». Он попросит подтвердить запуск.

Для docker-режима в том же окне есть вторая команда: она пишет токен в `/etc/srvmon/agent.token` и запускает оба контейнера.

Пока агент не вышел на связь с выпущенным токеном, сервер помечен **◌ ждём агента**.

## Токен агента

Панель хранит токены только в виде хеша, поэтому существующий токен показать нельзя, можно только выпустить новый:

- **«перевыпустить на сервере»** (если агент уже стоит и у панели есть SSH-доступ). Панель запишет новый токен на сервер сама, агент перейдёт на него в течение минуты.
- **«новый токен для ручной установки»**. Панель покажет токен и команды установки.

Старый токен продолжает работать, пока агент не выйдет на связь с новым. После этого старый отзывается автоматически, так что работающий агент не отваливается.

## Обновления

Панель обновляет агентов обоих режимов сама: автоматически один раз после выхода новой версии панели (`SRVMON_AGENT_AUTOUPDATE=false` выключает) или кнопкой «обновить агента». В режиме systemd панель кладёт новый бинарь рядом со старым и проверяет его. Затем агент замечает подмену и перезапускается, systemd поднимает новую версию. Если за 90 секунд новая версия не вышла на связь, возвращается прежний бинарь.

## Безопасность режима systemd

Сервис работает от root, но видит хост только на чтение: `ProtectSystem=strict`, `ProtectHome=read-only`, `NoNewPrivileges`. Из прав у него только `CAP_DAC_READ_SEARCH`, `CAP_SYS_PTRACE` и для S.M.A.R.T. `CAP_SYS_RAWIO`/`CAP_SYS_ADMIN` с чтением дисков SATA/NVMe. Ограничения: 256 МБ памяти, 50% одного ядра.

Бинарь принадлежит пользователю `srvmon`, поэтому панель обновляет его без sudo. Это равносильно членству в группе docker, которое нужно контейнерному агенту: кто управляет панелью, тот управляет агентом.

Бинарь по адресу `/agent/srvmon-agent-linux-*` панель отдаёт только по действующему токену агента. Сам скрипт `/agent/install.sh` секретов не содержит.

## Что видно в логах

В разделе «логи» показываются предупреждения и ошибки самого сервера, а не srvmon. Например, строки `pvedaemon: authentication failure; rhost=… user=root@pam` значат, что кто-то подбирает пароль к веб-интерфейсу Proxmox (порт 8006). Что с этим сделать:

1. Закрыть порт 8006 снаружи: только свои IP, VPN или SSH-туннель.
2. Включить 2FA для `root@pam` в интерфейсе PVE.
3. Поставить fail2ban с jail для `pvedaemon`.

AI-агент может проверить, открыт ли порт, и предложить команды. Изменения выполняются только после вашего подтверждения.

## Ручная установка из релиза

К релизам `v*` приложены `srvmon-agent-linux-amd64`, `srvmon-agent-linux-arm64` и `SHA256SUMS`. Обычно они не нужны: панель отдаёт бинарь своей версии сама.
